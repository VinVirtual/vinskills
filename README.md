# VinSkills

[![ci](https://github.com/VinVirtual/vinskills/actions/workflows/ci.yml/badge.svg)](https://github.com/VinVirtual/vinskills/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

My Claude Code skills in one marketplace: workflow and context tools (`vin-core`), media,
robotics and AI evaluation. Every skill lives in its own public repository with its own tests,
CI and licence. This repository only lists them, each pinned to a reviewed commit, and groups
them into four bundles.

![vin-site-qa on a demo page with deliberate mistakes: the phone screenshot in dark mode](https://raw.githubusercontent.com/VinVirtual/vin-site-qa/v1.0.0/examples/output/chromium-390-dark.png)

## Install

```bash
claude plugin marketplace add VinVirtual/vinskills
```

Then, inside Claude Code:

```
/plugin install vin-core@vinskills         # bundle: the eight workflow and context skills
/plugin install vin-media@vinskills        # bundle: every media skill
/plugin install vin-robotics@vinskills     # bundle: every robotics skill
/plugin install vin-ai-eval@vinskills      # bundle: every evaluation skill
/plugin install vin-meter@vinskills        # or any single skill by name
```

Or from your shell: `claude plugin install vin-core@vinskills`.

The four bundles have no skills of their own. Each one depends on its member plugins, so
installing a bundle installs them. Every member points at its own repository, pinned to a commit.

You can also skip the marketplace and clone any one skill as a plain skill folder, for example
`git clone https://github.com/VinVirtual/vin-meter ~/.claude/skills/vin-meter`.

Some skills need local tools (ffmpeg, Chrome, poppler, Python packages, MuJoCo, Blender). Each
skill's README lists them and has a `check_env.sh` that says how to fix anything missing.

## vin-core in one minute

With the skills cloned or installed, from each skill's folder:

```bash
node scripts/vin-meter.mjs 7d                   # vin-meter: where my tokens went this week
node scripts/vin-nav.mjs show parseConfig       # vin-navigator: one function, not the whole file
node scripts/vin-docs.mjs contract.pdf          # vin-docs: PDF to Markdown with page markers
npm test 2>&1 | node scripts/vin-squeeze.mjs    # vin-squeeze: long output, short read
gh api repos/o/r/issues | node scripts/vin-lens.mjs -e 'return count(data, i => i.state)'   # vin-scriptlens
node scripts/site-qa.mjs ./dist --out qa/       # vin-site-qa: screenshots, CSP, SEO, a11y, LCP/CLS
```

Inside Claude Code you do not type these: the skills tell Claude when and how to use them.
None of these tools calls a model or sends your data anywhere (vin-site-qa fetches the page you
point it at, and that is all). `vin-house-build` and `vin-agent-orchestration` are the house flow
for shipping with agents and the rules for briefing them.

## Philosophy

I build things I need, then make them good enough to share.

- **Local first.** If it can run on my own machine for free, it does. No accounts, no keys,
  no paid voice or video service in the default path.
- **Show the work.** Every skill ships with an example made by actually running it, and tests
  for the parts that can break. If a number is in a README, it came from a run.
- **Plain words.** A README should tell you what you get, what it needs and where it stops.
- **Small and checked.** One job per skill. Reviewed by a second pair of eyes before it goes
  public, then checked again from a fresh clone.
- **Safe by default.** Commands run without a shell, paths cannot escape their folder, nothing
  private goes into a repo, and anything that publishes asks first.

## How this repository works

| Path | What |
| --- | --- |
| `catalog.json` | Source of truth: every skill repository, its bundle, its pinned commit and one line about it |
| `.claude-plugin/marketplace.json` | The marketplace: four bundles, then one plugin per skill repository (generated) |
| `plugins/vin-core/`, `vin-media/`, `vin-robotics/`, `vin-ai-eval/` | Bundle manifests, dependencies only (generated) |
| `scripts/build-marketplace.mjs` | Writes the marketplace, the bundle manifests and the table above (`--pin` moves pins to each repository's latest commit, `--check` for CI) |
| `scripts/validate.mjs` | Lints the marketplace, the catalog and the bundle manifests |
| `tests/` | `npm test` runs offline; `npm run test:online` checks that every pinned repository is public and has a SKILL.md with the right name and a licence at the pinned commit |

Adding or updating a skill: push it to its own repository, add or edit its entry in
`catalog.json`, run `node scripts/build-marketplace.mjs --pin`, review the diff, `npm test`,
`npm run test:online`, commit.
