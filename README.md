# VinSkills

[![ci](https://github.com/VinVirtual/vinskills/actions/workflows/ci.yml/badge.svg)](https://github.com/VinVirtual/vinskills/actions/workflows/ci.yml) [![License: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)

My Claude Code skills in one place, installable as plugins: media, robotics and AI evaluation,
plus `vin-core`, the workflow and context tools I use every day.

![vin-site-qa on a demo page with deliberate mistakes: the phone screenshot in dark mode](examples/site-qa/output/chromium-390-dark.png)

## Install

> These commands work once the repository is published on GitHub. Until then, use the local
> path in "Try it from a folder" below.

```bash
claude plugin marketplace add VinVirtual/vinskills
```

Then, inside Claude Code:

```
/plugin install vin-core@vinskills         # workflow and context tools (built here)
/plugin install vin-media@vinskills        # bundle: every media skill
/plugin install vin-robotics@vinskills     # bundle: every robotics skill
/plugin install vin-ai-eval@vinskills      # bundle: every evaluation skill
/plugin install reel-studio@vinskills      # or any single skill by name
```

Or from your shell: `claude plugin install vin-core@vinskills`.

The three bundles have no skills of their own. Each one depends on its member plugins, so
installing a bundle installs them. Every member points at its own repository, pinned to a
reviewed commit.

Some skills need local tools (ffmpeg, Chrome, Python packages, MuJoCo, Blender). Each skill's
README lists them and has a `check_env.sh` that says how to fix anything missing.

### Try it from a folder

```bash
git clone <this repository> vinskills
claude plugin marketplace add ./vinskills
claude plugin install vin-core@vinskills
```

## vin-core in one minute

```bash
S=plugins/vin-core/skills
node $S/vin-burn/scripts/vin-burn.mjs 7d                    # where my tokens went this week
node $S/vin-navigator/scripts/vin-nav.mjs show parseConfig  # one function, not the whole file
node $S/vin-docs/scripts/vin-docs.mjs contract.pdf          # PDF to Markdown with page markers
npm test 2>&1 | node $S/vin-squeeze/scripts/vin-squeeze.mjs # long output, short read
gh api repos/o/r/issues | node $S/vin-scriptlens/scripts/vin-lens.mjs -e 'return count(data, i => i.state)'
node $S/vin-site-qa/scripts/site-qa.mjs ./dist --out qa/    # screenshots, CSP, SEO, a11y, LCP/CLS
```

Inside Claude Code you do not type these: the skills tell Claude when and how to use them.
Everything runs locally. None of these tools calls a model or sends your data anywhere
(vin-site-qa fetches the page you point it at, and that is all).

## Philosophy

I build things I need, then make them good enough to share.

- **Local first.** If it can run on my own machine for free, it does. No accounts, no keys,
  no paid voice or video service in the default path.
- **Show the work.** Every skill ships with an example made by actually running it, and tests
  for the parts that can break. If a number is in a README, it came from a run.
- **Plain words.** A README should tell you what you get, what it needs and where it stops.
- **Small and checked.** One job per skill. Reviewed by a second pair of eyes before it goes
  public, then checked again from a fresh clone.
- **Safe by default.** Commands run without a shell, paths cannot escape their folder, nothing
  private goes into a repo, and anything that publishes asks first.

## How this repository works

| Path | What |
| --- | --- |
| `.claude-plugin/marketplace.json` | The marketplace: `vin-core`, three bundles, and one plugin per skill repository |
| `catalog.json` | Source of truth for the skill list, themes and pinned commits |
| `scripts/build-marketplace.mjs` | Writes the marketplace, bundle manifests and the table above from `catalog.json` (`--pin` moves pins to the latest commit, `--check` for CI) |
| `scripts/validate.mjs` | Lints every manifest and SKILL.md |
| `plugins/vin-core/` | The plugin built here, with eight skills |
| `plugins/vin-media/`, `vin-robotics/`, `vin-ai-eval/` | Bundle manifests (dependencies only) |
| `tests/` | `npm test` runs everything offline; `npm run test:online` also checks that every pinned source exists and is public |

Updating a skill: push it to its own repository, then `node scripts/build-marketplace.mjs --pin`,
review the diff, `npm test`, commit.
